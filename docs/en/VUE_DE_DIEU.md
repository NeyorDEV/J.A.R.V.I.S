# God's Eye View

[God's Eye View](https://github.com/bilawalsidhu/gods-eye-view) (MIT license for the code; third-party data and 3D models under their own
licenses, sometimes non-commercial: see its `LICENSE` and `DATA_SOURCES.md`) is a live 3D globe web app: airplanes, ships,
satellites, earthquakes, fires, public cameras, weather.

**It is not included in this repository.** Each user installs it if they want, from the latest GitHub release.

## What JARVIS does

| You say | JARVIS |
|---|---|
| "enable / launch / open God's eye view" | Installed: launches the local server and displays the app in full screen. Not installed: asks "God's Eye View is not installed on this computer. Would you like to install it?" (voice or YES / NO HUD buttons), then downloads, installs, and opens it. |
| (installed, newer release) | Prompts for an update once per version ("A new version… is available. Would you like to update it?"). Checked once per day. |
| "update God's eye view" | Installs the latest release if it is newer, without asking. |
| "go to Tokyo", "show me Paris" (view open) | Moves the camera (shareable link `#v=2&lat=…&lon=…`). |
| "close God's eye view" (or the cross, Esc) | Closes the view and stops the server. During an installation: cancels it. |

## What is where

- `data/gods_eye_view/app/`: the app (GitHub release, without its demo GIFs and issue templates) + `jarvis.vite.config.mjs`.
- `data/gods_eye_view/node/`: portable Node.js 24, only if the computer does not have Node 24.14+ or 26 (official zip, verified checksum;
  nothing is installed in Windows).
- `data/gods_eye_view/version.json`: installed version, last check, declined version.
- `data/gods_eye_view.log`: server and `npm ci` output.
- Everything in `data/gods_eye_view/` is in `.gitignore`: never versioned.

## The app is never modified

It refuses to be displayed in another page (`X-Frame-Options: DENY`, `frame-ancestors 'none'`), except in `?embed=1` mode which hides all of its
HUD. `jarvis.vite.config.mjs` (written by `backend/module/vue_de_dieu.py` on every startup) wraps its Vite config and only allows the
HUD origins (`http://localhost:5173`, `http://127.0.0.1:5173`). Updating a release = new folder; nothing to re-patch.

## Installation, in detail (`module/vue_de_dieu.installer`)

1. System Node 24.14+ (or 26), otherwise portable Node 24 LTS downloaded from nodejs.org.
2. GitHub release (`/releases/latest`, zip archive) downloaded with progress, extracted without `docs/media`, `.github`, `changelog.d`, `pinokio`.
3. `npm ci` (with `PUPPETEER_SKIP_DOWNLOAD=1`): 2 to 5 minutes.
4. The old version is replaced only at the end: a failure or cancellation (closing the installation screen) leaves it intact.

Prerequisites: 64-bit Windows, access to GitHub and nodejs.org, about 500 MB of disk space.

## API Keys

God's Eye View saves its keys in ITS `.env` (`data/gods_eye_view/app/.env`, unversioned), entered in its "Power up" panel. JARVIS does not pass any of its keys to it (filtered environment, `_environnement()`). On OpenAI and Gemini cards without a key, the "USE JARVIS'S KEY" button copies the key from JARVIS's `.env` to the app's (via its own endpoint); after that, both are independent: changing one does not change the other. The button comes from a script added to the page by `jarvis.vite.config.mjs` (the app is not modified); it only exists in JARVIS's HUD.

Keys added by JARVIS in this panel (`jarvisCles` plugin): **MÉTÉO-FRANCE** (`METEOFRANCE_API_KEY`, rain radar) and **WINDY WEBCAMS** (`WINDY_WEBCAMS_API_KEY`, cameras). They are written to the app's `.env` (key up to 4,096 characters: the Météo-France token is ~1,500, the original limit is 512); `module/gev_cles.py` reads them back on the Python side, with fallback to JARVIS's `.env`. After saving, relaunch the view for the radar to appear.

## French cameras

God's Eye View accepts a "sources pack" (JSON file, `CCTV_SOURCES_FILE`) in addition to its ~4,000 built-in cameras. `module/gev_cameras_fr.py` writes `data/gods_eye_view/cameras_france.json` before each server start (refreshed in the background after one day; without network the old one is kept): currently 15 cameras from the Métropole de Lyon (Open License 2.0). `CCTV_FORCE_AUSTIN=1` is required: without it the app ONLY loads the custom pack. Image reload rate: the app sets it per provider (`src/data/cctvLod.js`, default 5 minutes); `CADENCES_JARVIS` in `_CONFIG_VITE` (vue_de_dieu.py) adjusts it to the file's service (Lyon: 60 s). Adding a source = a `_source_xxx()` function in SOURCES. Open-reuse data only (neither Bison Futé, nor DIR, nor motorway companies: no license). Lead: Loire-Atlantique (5 webcams, live images, coordinates to be provided).

**Windy**: with `WINDY_WEBCAMS_API_KEY` (api.windy.com/keys, "Webcams API", free), `module/windy_relais.py` adds webcams for an area, active or not (an inactive one is kept: its image is served only once it becomes active again) (`CENTRES_WINDY`, 50 km around Saint-Étienne: 38 webcams) and serves their images through a local relay (127.0.0.1:8766), because the API provides URLs that expire in 10 to 15 minutes. A single list is requested again every 8 minutes, never the history, never "all webcams" (prohibited by Windy terms). Attribution "Webcams provided by windy.com" carried by the `credit` field. Personal use: the terms are not explicit for a local app, do not distribute JARVIS with a key.

- **Rain radar France** (`module/gev_radar_fr.py`, "radar-france" product of `jarvisMeteosat`): Météo-France "Données radar" API (`METEOFRANCE_API_KEY`, free API subscription on portail-api.meteofrance.fr), 500 m / 5 min rainfall depth in HDF5 ODIM, converted to dBZ equivalent (Marshall-Palmer) and reprojected (polar stereographic -> longitude / latitude 12°W-12°E, 40°N-52°N). - **Layers added by JARVIS** (`module/gev_couches.js`, plugin `jarvisCouches`): new layers without modifying the app, via `window.__gevQaRegisterLayer` (exposed by the app in development mode, which the JARVIS server does). A layer = a function returning `{ id, name, icon, source, updateInterval, init, enable, disable, update, destroy, getStats, getParams, setParams, getRowControls }`, rendered with Cesium (`window.__CESIUM__`). Data: files downloaded by JARVIS in the background and served on `/__jarvis/<nom>.json` (503 as long as they are missing). First layer: **Fuel prices · France** (`module/gev_carburants_fr.py`, prices from ~9,500 stations, data.economie.gouv.fr). Not in share links.
  Panel organization: `PLACEMENT_COUCHES` (`jarvisCouches` plugin in `module/vue_de_dieu.py`) adds each layer's ID to the appropriate group in `PANEL_GROUPS` (Movement, Events, Weather, Utilities…); a layer missing from this list would fall under "Other layers".
- **French open data layers** (`module/gev_donnees_fr.py`, `fabrique()` in `module/gev_couches.js`): EV charging (IRVE ~120 MB CSV grouped by station, 27,800 stations), floods (Vigicrues, levels 1 to 4 by river section), earthquakes (EMSC FDSN, 30 days), air quality (Open-Meteo CAMS Europe, ~100 cities, EAQI index), parking (static: BNLS, Saemes, Indigo, Saint-Étienne, Orléans, ~1,460; live, every 5 minutes: Nantes, Aix-Marseille, Tours, Clermont-Ferrand, ~100 parking lots with available spaces; no national source, each city publishes in its own format, often Opendatasoft `exports/json`; deduplication within 60 m, live takes precedence; voice search "find me parking in X": `module/gev_parkings.py`), drones (IGN WFS `TRANSPORTS.DRONES.RESTRICTIONS:carte_restriction_drones_lf`, ~90,000 polygons: fetched by viewport, BBOX in longitude, latitude order). Adding a point layer = a `fabrique()` spec (build, sheet, buttons, legend) + a dataset in `gev_donnees_fr.JEUX` + its name in the plugin whitelist.
- **Seveso: substances**: with `GEORISQUES_API_KEY` (free token, georisques.gouv.fr/inscription, valid ~1 year), `module/gev_donnees_fr.py` queries `/api/v2/installations_classees/{codeAIOT}` (`Authorization: Bearer` header) for each site and keeps ICPE 4xxx sections. The filtered v2 list (`statutSeveso=SEUIL_HAUT|SEUIL_BAS`, `pageNumber` starting from 0, 1,000 per page) works in a single query but lacks the sections; the v1 sweep serves as the base.
- **Electricity, drought, traffic, Seveso, bathing water** (keyless, `module/gev_donnees_fr.py` → files `electricite|secheresse|trafic|seveso|baignade.json`, relay `/__jarvis/donnees/<nom>.json`): regional éco2mix (ODRÉ API, latest complete value per region, 15 min), VigiEau (`api.vigieau.beta.gouv.fr/api/departements`, levels per usage, 3 h), Bison Futé (DATEX II `…/Evenementiel-DIR/grt/RRN/content.xml`, ~3.7 MB, ongoing events, 10 min; DIR network, not franchised highways), Géorisques (`/api/v1/installations_classees`, the `statutSeveso` filter does not work: scans pages of 1,000 and filters locally, once a week), bathing water quality (data.gouv.fr CSV, ranking). The data.gouv.fr API is sometimes unavailable: `maj_baignade` falls back to the known CSV URL.
- **Avalanche risk** ("Avalanche risk · France" layer, `avalancheFrance()` in `module/gev_couches.js`): Météo-France BRA bulletins, keyless (open archive `files.data.gouv.fr/meteofrance/data/BULLETIN/BRA/{année}/{mois}/{jour}/xml/`, massif outlines: geojson resource from the "Archive des bulletins avalanches" dataset on data.gouv.fr, kept for 6 months in `massifs.json`). `avalanche.json` file rebuilt every hour (latest folder of the day, fallback up to 10 days). The official API (`DPBRA`) requires a subscription; the open archive is sufficient.
- **Météo-France weather alerts** ("Weather alerts · France" layer, `alertesFrance()` in `module/gev_couches.js`): API `public-api.meteofrance.fr/public/DPVigilance/v1/cartevigilance/encours` (key subscribed to "Bulletin Vigilance"; without subscription: 403). Domains: department code (levels 1 to 4 across phenomena 1 to 9), code + "10" = coastal zone, "FRA" = national (ignored). Forecast periods D and D+1. Boundaries in `data/gods_eye_view/donnees/departements.json` (6 months). Forest fire and avalanche weather APIs each require their own subscription (same token).
- **French localization** (`module/gev_fr.json`, `MODIFS_FR` overrides in `jarvisCouches` plugin, `tr()` in `module/gev_couches.js`): translated app catalog (same format as es / ru / zh-CN: English text = key, three plural forms), default language set by JARVIS.
